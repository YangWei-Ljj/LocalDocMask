# ADR-002：候选实体默认按风险/来源分流，而非默认确认

- 状态：Accepted
- 日期：2026-10-26
- 决策者：架构组

## 背景

现状：`Candidate.confirmed` 默认 `True`（`models.py:46`）；公司正则命中即以 `confidence=0.85` 但仍走默认确认（`detection.py:51`）；批量按钮强制全部 `confirmed=True`（`gui.py:474-476`）。结果是"中国石油股份有限公司"等公开企业名以及"我们公司/有限公司/集团公司"等泛指被不加区分地自动脱敏（P0-1、P1-1）。

总控指令要求：公开企业名既不一律放行也不一律脱敏；高风险且无法确定的内容进入人工复核；不能确定安全时不得自动导出。

## 决策

候选实体不再一律 `confirmed=True`，而是在识别/融合阶段依据 **实体类型 + 来源 + 校准置信度 + 上下文 + 知识词库** 给出三档处置：

| 处置档 | 触发条件（默认策略） | confirmed |
|---|---|---|
| AUTO_CONFIRM（自动确认） | 高精度且通过校验的规则实体（身份证/手机/邮箱/银行卡/护照/固定电话）；黑名单命中；高置信度领域词 | True |
| NEEDS_REVIEW（人工复核） | 公司名/姓名/地址等上下文相关实体；公开企业名；仅模型来源；置信度中等；规则与模型冲突 | False（待裁决） |
| SUPPRESS（抑制） | 泛指引用（我们公司/有限公司/集团公司/银行医院大学等）；白名单命中；非实体的低置信度匹配 | False（不进入活跃处理） |

- 用户可在复核界面把 NEEDS_REVIEW 项改为确认或放行（显式裁决）。
- 引入 `RiskLevel`（LOW/MEDIUM/HIGH/CRITICAL）与 `decision_reason`，使每条判定可解释。

## 导出门禁联动

- 交互模式：存在未被用户显式裁决的 NEEDS_REVIEW 项时，禁止导出。
- 批量自动模式：仅处理 AUTO_CONFIRM 项；含 NEEDS_REVIEW 项的文件保持"待复核"，不自动导出（失败关闭，见 ADR-003 与数据流文档）。

## 后果

- 正面：从根上消除"公司名一律自动脱敏"，为误报治理提供分流机制；判定可解释。
- 负面：交互步骤增加；批量自动模式的自动导出范围收窄（这是预期的安全行为）。
- 约束：不得为降低误报而整体关闭检测，也不得为提高召回而把所有公司/产品名判为敏感。
