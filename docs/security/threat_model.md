# LocalDocMask 安全设计与威胁模型

> 本文以 `master` 当前代码为依据，描述信任边界、数据流、敏感资产、威胁与缓解、
> 以及残余风险。目标不是宣称"绝对安全"，而是把**哪些地方默认失败关闭、哪些地方必须人工兜底**讲清楚。

## 1. 信任边界

```
┌────────────────────────── 信任边界：本机、单用户、默认离线 ──────────────────────────┐
│                                                                                    │
│  用户文件(原件,只读)  ──►  解析/识别  ──►  脱敏处理(受控目录)  ──►  独立审计  ──► 成功产物
│                              │                                  │
│                              ├─► SQLite(tasks.db,只存掩码值)     ├─► 隔离目录(失败关闭,含原文,不外发)
│                              ├─► 日志(data/logs,RedactionFilter)└─► 审计记录 JSON(只计数/哈希/掩码值)
│                              └─► 可选:本地 Ollama(仅回环)        可选:映射文件(data/mapping,默认不写)
│                                                                                    │
└──────────────────────────────────────────────────────────────────────────────────────┘
        ▲ 边界外：公网、其他用户进程、外部存储——默认不可达、不写入
```

- **边界内**：本机文件系统、本机回环 Ollama、本机 SQLite/日志/临时目录。
- **边界外默认不可达**：唯一出站调用是 Ollama，硬编码回环白名单（`127.0.0.1/localhost/::1`），
  `requests.Session` 关闭 `trust_env` 并清空代理；配置层再次拒绝非回环地址（`settings.py::_validate`）。
- **原件在边界内但只读**：处理前后 SHA-256 比对，变化即停止导出（`pipeline.py::finalize`）。

## 2. 敏感资产清单

| 资产 | 存放位置 | 保护措施 |
|---|---|---|
| 原始文档（原件） | 用户自选路径 | 只读；哈希绑定；绝不覆盖/删除 |
| 识别出的实体原文 | 内存 Candidate | 落库/落日志前强制 `mask_display`；内存中不持久化原文 |
| 一致性映射表（真实值→虚构值） | 默认仅内存 | 默认 `persistence=memory`；落盘需显式 opt-in 且 `icacls` 收紧为仅当前用户；`__repr__` 不泄露 |
| 任务数据库 | `data/tasks.db` | `task_items` 只存掩码值；`audit_findings.detail` 落库前 `sanitize_detail`；gitignored |
| 日志 | `data/logs/*.log` | `RedactionFilter` 对高风险模式与登记候选值掩码；按大小/天数轮转 |
| 审计记录 JSON | processing/成功目录 | 只含计数、源/终态哈希、掩码值，不含原文 |
| 中间/隔离产物 | `data/processing/`、`data/output/quarantine/` | 隔离产物可能含原文，**不外发**；可一键清理临时目录 |

## 3. 威胁与缓解

### T1 路径越权 / 目录逃逸
- **威胁**：文件名或任务对象中的 `..`、绝对路径、符号链接把产物写到数据目录之外（覆盖系统/用户文件）。
- **缓解**：所有落盘路径经 `security/path_safety.py::safe_join / resolve_within` 收口，
  拒绝绝对路径段与 `..` 段，最终再做一次 resolve 判定（兜住符号链接），逃逸抛 `SecurityViolation`（失败关闭）。

### T2 数据外发 / 网络泄露
- **威胁**：识别结果或文档内容被发到外部服务。
- **缓解**：无公网出站代码路径；Ollama 客户端双重回环校验 + 禁代理（`ollama.py`）；Ollama 默认 `enabled=false`。
  本地 OCR（RapidOCR/onnxruntime）离线推理。

### T3 日志/数据库泄露原文
- **威胁**：调试日志、审计 finding、异常消息把手机号/身份证/公司名明文写盘。
- **缓解**：
  - 日志 `RedactionFilter` 同时掩码 `record.msg`、`args` 与所有非保留 `extra` 属性（修复了 `extra={event: phone}` 直落盘的历史缺陷）；
  - 扫描后把当次候选原文登记进 `register_sensitive_values`，日志输出前统一替换为掩码；
  - SQLite `save_task` 中条目一律写 `mask_display`，`audit_findings.detail` 经 `sanitize_detail` 过高风险正则 + 候选原文替换。

### T4 脱敏后残留（漏报）
- **威胁**：正文换了，但脚注/尾注/批注/元数据/隐藏 XML/图片里的敏感内容还在。
- **缓解**：独立 `Auditor` 与处理模块分离，重新提取正文、OCR 复查、检查 PDF 元数据/附件/表单字段、
  DOCX 嵌入图像与脚注尾注部件、XLSX 隐藏表与 zip 内 XML；高风险模式在输出中复扫。
  发现残留 → 条目进入删除流程并二次验证；整文件仍残留 → finalize 阻断并隔离。

### T5 替换失败 / 写坏文件
- **威胁**：某条替换没生效、或输出文件损坏不可读。
- **缓解**：逐项 `residual_terms` 检查；无法验证（uncheckable）按残留处理；输出缺失或终态哈希与审计时不一致 → 阻断。
  格式处理器失败必须抛异常，不静默成功。

### T6 崩溃 / 中断后误判安全
- **威胁**：处理中途崩溃，残留产物被当成成功输出。
- **缓解**：`RecoveryService` 启动时重归类 PROCESSING 任务——无输出可安全重试回 PENDING；
  已有残留输出则标记 `INTERRUPTED`，**不自动认定安全**。finalize 还有源哈希/终态哈希/未决项多重门禁。

### T7 OCR 漏检 / 误检
- **威胁**：图片或扫描页文字识别不全，或误识别。
- **缓解**：OCR 命中区域做像素级黑块并二次审计；OCR 失败抛 `UNCHECKABLE`（按不安全处理）；
  PDF 图文混排页（图片多、文字少到无法可靠定位）产生 `review_flags`，自动批次下整文件挂起复核。
  **残余风险**：OCR 本身的漏识别无法由系统发现，重要图片需人工核对。

### T8 本地模型不可靠 / 被诱导
- **威胁**：LLM 输出错误实体，或被文档内容诱导。
- **缓解**：模型输出仅为候选（`source=ollama`，低权重 0.55）；融合时"仅模型来源的非高精度类"降权 0.15 并转复核；
  模型异常被捕获、不中断主流程；模型不参与"是否残留/可否导出"的最终判定（由规则+独立审计+人工闭环）。

### T9 宏 / 外部链接 / OLE 等无法可靠清除的内容
- **威胁**：VBA 宏、外部链接、嵌入对象里藏有无法文本化的敏感内容。
- **缓解**：XLSX/XLSM 检出宏/外部链接/OLE 即在 extract 警告、process 直接抛错阻止导出；
  PDF 含表单字段值同样阻止导出；审计发现仍含宏/附件/OLE 会记 `NEEDS_CONFIRM`。

### T10 资源耗尽
- **威胁**：超大文件/超长任务导致卡死或内存溢出。
- **缓解**：入口按 `ResourceLimits` 拒绝超大文件（默认 50MB）；单任务协作式超时（默认 1800s，阶段边界检查，超时失败关闭）；
  GUI 后台线程数收敛到配置上限（默认 2）。

## 4. 关键安全机制对照

| 机制 | 代码位置 | 作用 |
|---|---|---|
| 哈希绑定 | `security/hashing.py`、`pipeline.py::finalize` | 原件/输出前后哈希一致才放行 |
| 路径越权防护 | `security/path_safety.py` | 产物不出受控目录 |
| 日志脱敏 | `infrastructure/logging/logger.py::RedactionFilter` | 日志不落原文 |
| 回环/禁代理 | `infrastructure/llm/ollama.py`、`settings._validate` | 不外发 |
| 独立审计 | `security/auditor.py::Auditor` | 与处理分离的残留复查 |
| 失败关闭/隔离 | `pipeline.py::finalize`、`batch.py` | 任何门禁不过即隔离 |
| 映射保护 | `security/redaction/mapping.py` | 默认不落盘、落盘最小权限、不导出明文 |
| DB 掩码落库 | `persistence/sqlite_repo.py::sanitize_detail` | 库中无完整原文 |

## 5. 残余风险与人工复核规则

系统**不能**自动消除以下风险，因此默认把相关文件**挂起人工复核而非自动导出**：

1. **OCR 漏检**：图片/扫描件中模型没认出的文字，系统无法自查 → 重要图片人工核对。
2. **图文混排 PDF**：印章、签名等嵌入图像内容无法可靠定位删除 → 产生 review_flags，挂起复核。
3. **公开企业名**：既不一律遮也不放行 → NEEDS_REVIEW，由人判断该合作方是否需要脱敏。
4. **短标签误命中**：公司正则可能命中"内部公司"之类标签 → 落到待复核，人来放行。
5. **合成样本外推**：F1=1.0 来自 36 条合成句，不代表真实文档精度 → 真实文件仍需抽检。
6. **隔离产物**：隔离目录文件可能含原文，仅用于排查，**不得对外发送**。

**人工复核的最小规则**：导出前必须确认（a）没有黄色待复核项遗留；（b）审计报告结论为"通过"；
（c）隔离目录里没有你打算对外发送的文件。只要有一条不满足，就不要导出。
